# 手机端架构与契约基线

> **状态：逐项确认中（2026-08-23 起）**

## 产品边界

手机是远程客户端，不是权威数据库，也不承载 Pi runtime。它通过 WSS Relay 与电脑 Connector 建立应用层 E2EE 链路。

## 模块边界

```text
Features/UI
  -> Session State Machine
  -> Use Cases / Command Policy
  -> Connector Service Client
  -> E2EE + WSS Transport
  -> Secure Storage（密钥）/ Ephemeral Memory（业务会话）
```

跨端依赖只允许：Relay Transport、Connector Service、E2EE 测试向量、integration-profile。不得依赖 Connector 的内部数据库、Pi RPC、Prompt、文件路径或 Relay 内部数据库。

## P0 状态和数据

- 链路状态：`UNPAIRED`、`CONNECTING`、`NOT_READY_RELAY`、`NOT_READY_CONNECTOR`、`NOT_READY_STORAGE`、`UNKNOWN`、`READY`。
- 提交状态：`DRAFT -> SENDING -> UNKNOWN_RESULT`，仅收到 Connector 持久接收回执后展示“电脑已接收”。
- Projection 只在当前前台会话内存存在；只接受更高 `event_version`。
- Card Command 在线发送，携带 `event_id`、命令和 `expectedVersion`；断线或版本冲突不得自动重发。
- 原文追溯在线发送按需请求，只携带当前卡片的 `event_id`；`capture_id` 和 `log_entry_id` 不进入手机公开契约。响应只在当前会话内存展示，不进入 Projection 缓存，失败、断线或 App 退出后不自动重试或恢复。
- Noise 静态密钥在端点生成和安全存储：Connector 首次启动生成并持久化其静态密钥，Phone 在扫码配对后生成并保存自己的静态密钥；双方将静态公钥指纹与 `pairing_id` 绑定，并在握手完成后校验匹配。Relay 只保存公钥和 pairing 元数据，不保存私钥。
- Noise transport 在 P0 不使用会话内自定义 rekey 控制帧；会话重建时由 Phone 重新发起完整 Noise 握手，Connector 重新响应。单会话时长/消息量限制与失败恢复语义必须由 Spike 和契约证据补齐。
- Noise transport 每个会话按方向维护单调递增 `uint64` 应用层序号，序号随密文封套传输；接收端拒绝重复或回退序号。新会话完成握手后序号从初始值重新开始；正式字段位置、乱序窗口和错误映射仍待契约冻结。
- Noise 握手采用固定总超时，P0 初始值为 `10 秒`；所有握手失败对 Phone 统一映射为脱敏错误 `HANDSHAKE_FAILED`，底层失败原因只保存在端点本地诊断。该数值和重连退避仍需 Spike 验证。
- 握手失败后的前台自动重连采用指数退避：首次可立即触发，随后按 `1s/2s/4s/8s/16s` 递增并封顶；成功握手后清零退避计数。后台生命周期、网络恢复触发、`1 秒` 去抖、网络类型切换和前台重连策略已确认（Q-PH-2026-029/030/031/032/033），见以下四条。
- Phone 进入后台或被系统挂起后不保持 Noise 长连接、不执行持续自动重连；回到前台时保留内存中的退避状态，重新发起一次健康检查和完整 Noise 握手。不得持久化业务正文、待发送队列或自动重发任务来支持后台恢复。
- 网络从不可用恢复为可用时，只解除“不可连接”阻塞，不跳过当前退避计时；没有退避计时才立即尝试 Noise 重连，否则等待当前计时到期。网络恢复事件不得重置退避计数。
- 网络恢复事件采用 `1 秒` 去抖窗口；窗口内只保留最后一次“网络可用”事件，去抖不改变退避计时或计数。
- Wi-Fi、蜂窝网络或网络接口切换视为当前传输会话可能失效；Phone 关闭旧 WSS/Noise 会话，沿用现有退避和 `1 秒` 去抖规则重新建立链路，不在旧路径上继续发送业务密文。
- Relay 对每个 `pairing_id` 维护握手尝试限流；超限统一映射为脱敏错误 `RATE_LIMITED`，不建立离线业务队列。Relay 同时维护全局握手并发/速率保护；任一保护层超限均返回 `RATE_LIMITED`，全局保护不能替代 pairing 级限流。全局参数、容量校准及 Caddy/应用层职责边界待容量 Spike 冻结。
- Relay pairing 级握手限流初始参数为 `60 秒`窗口最多 `5 次`；窗口自然过期后恢复。该值仅是容量 Spike 初始假设，最终参数须由压力证据校准。
- Relay 全局握手保护的容量 Spike 初始基线为最多 `100` 个并发握手、每 `60 秒`最多 `300` 次握手尝试；该基线不代表最终容量承诺，最终参数及 Caddy/应用层职责边界须由 E3 Spike 证据冻结。

## 契约策略

契约先定义 Schema、错误码、版本兼容范围和脱敏 fixtures，再生成/编写手机内部类型。原文追溯请求/响应属于 Connector Service 公开契约；Relay 只转发端到端密文，不建立队列或落盘。Relay ACK 只能证明路由层收到，不能替代 Connector 持久接收、事务提交或 Projection。
