# 架构分层与仓库边界

## 跨端总链路

```text
手机客户端 <-> WSS Relay（身份与密文路由） <-> PC Connector <-> Utell Pi 插件/Adapter
```

手机负责采集、状态展示和卡片交互；Relay 负责身份、配对、公钥登记、撤销、单主 Connector 路由、密文路由、ACK、重连、限流和最小脱敏审计；PC Connector 负责权威库、Pi 解析、事务和 Projection；应用层 E2EE 由手机与 Connector 端点负责。

## 本端角色（内部建议分层）

```text
UI/Feature
  -> Session & State Machine
  -> Use Case / Command Policy
  -> Contract Client（WSS + E2EE）
  -> Secure Storage / Ephemeral Memory
```

- UI 只观察状态，不自行判断业务成功。
- 状态机集中定义 `UNPAIRED`、`CONNECTING`、`NOT_READY_*`、`UNKNOWN`、`READY`。
- 协议客户端只处理版本化契约、序号、验签、重放和错误映射。
- 业务原文、提交任务和 Card Projection 只允许当前会话内存存在，除非后续 Q&A 明确改变 PRD。

## 本端角色（不得越界）

- 不读取 PC 数据库或 Pi RPC 原始接口。
- 不在手机实现业务权威写库、离线重放或通用 Agent 工具。
- 不把 Relay 的可达性等同于 Connector 的事务状态。
- 不为方便测试复制一份与公开契约不一致的“手机专用协议”。
