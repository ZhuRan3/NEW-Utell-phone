# harness 开发与验证规范

## 目的

harness 是可重复验证跨端边界的测试架构，不是产品运行时，也不承载真实用户数据。它必须能在没有对端真实实现的情况下验证本端的公开协议行为。

### 本端角色（验证目标）

在没有真实 Relay、Connector 或 Pi 的情况下验证手机状态和协议行为。

## 固定目录

```text
harness/
├── harness.yaml       # 版本、Owner、命令和边界
├── README.md
├── 契约/              # 公开 Schema、错误码和兼容说明
├── fixtures/          # 脱敏、最小、可审查的输入输出样本
├── mocks/             # 对端模拟与密钥测试替身
├── scenarios/         # Given/When/Then 场景和故障注入
├── evidence/          # 测试报告、日志摘要和校验和
└── scripts/           # 可重复执行脚本，不放密钥
```

## 场景要求

每个场景必须写明前置状态、输入、预期状态、可见结果、不可发生的副作用和证据位置。任何新增契约先写 Schema/fixture，再写 mock 和产品实现。

### 本端角色（最低场景清单）

至少覆盖配对失败、READY 门禁、Relay ACK 与持久接收区分、未知结果、乱序版本、版本冲突、撤销、重启恢复和无原文残留。

## 数据要求

- fixture 不得使用真实 Capture 原文、标题、摘要、密钥或账号标识。
- 测试密钥必须是一次性合成值，并注明用途。
- 场景要可重复、可并行、可离线运行，不依赖外部网络或开发者本机状态。
