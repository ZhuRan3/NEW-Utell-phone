# Spikes（一次性技术验证）

> 本目录保存高风险未知的一次性验证（Spike）。Spike 代码是探索产物：**只有结论被用户批准、代码重构并补齐正式测试后，才允许进入生产目录**。
> 每个 Spike 一个子目录，命名 `SPK-PH-YYYY-NNN-主题/`，必须包含 README（合同）与结果记录。

## Spike 合同必填

1. 假设：只写一个可证伪的技术假设。
2. 环境：OS/设备/版本/配置。
3. 阈值：成功、失败、需记录的指标。
4. 步骤：可复现命令。
5. 原始结果：数据、日志、失败样本（不只保留成功截图）。
6. 解释：观察事实与推断分开。
7. 对决策的影响：支持/否定/仍未知；代码丢弃/保留/转正式测试。
